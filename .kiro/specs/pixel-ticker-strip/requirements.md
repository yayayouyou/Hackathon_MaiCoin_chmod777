# 需求文件 — TickerStrip 行情跑馬燈修正

## 簡介

`frontend-pixel` 畫面最上方的行情跑馬燈（TickerStrip）目前顯示的資訊不可信：價格來自
`api/mock.ts` 硬寫的種子加隨機漫步，與現實市價脫節；每欄只印 base 代號（如 `BTC`），
看不出計價幣別；幣種清單在元件與資料層各寫死一份，容易錯配；徽章不論資料真假都寫死
「MAX · 即時」。

本次要讓這條 bar 說真話：接真實 MAX 行情、標明交易對與計價幣別、只跑主流大幣，並在
拿不到資料時誠實降級。跑馬燈是整個像素世界「看起來是活的」的主要證據，因此所有改動
都不得破壞既有的「骨架固定、`#hud-root` childList 變動為 0」約束。

---

## 需求 1 — 明確標示交易對與計價幣別

**使用者故事：** 作為訪客，我想在跑馬燈上直接看出每個價格是哪個交易對、以什麼幣別計價，
這樣我才不會把台幣報價誤讀成美元。

### 驗收條件

1. **AC-1.1** WHEN 跑馬燈渲染任一欄位 THEN 系統 SHALL 同時顯示 base 資產與計價幣別，
   格式為 `BASE/TWD`（例如 `BTC/TWD`）。
2. **AC-1.2** THE 系統 SHALL 只顯示 TWD 計價的市場。
3. **AC-1.3** WHERE `Ticker` 資料模型被使用 THE 系統 SHALL 包含 `quote` 欄位，
   使計價幣別可從資料層追溯而非由 UI 硬編碼假設。
4. **AC-1.4** IF 某欄位尚無資料 THEN 系統 SHALL 保留交易對標籤並以佔位符（`—`）呈現價格，
   而非隱藏整欄。

---

## 需求 2 — 價格正確且可追溯來源

**使用者故事：** 作為訪客，我想相信看到的數字反映真實市價，這樣 demo 才有說服力。

### 驗收條件

1. **AC-2.1** THE 系統 SHALL 由真實 MAX 交易所行情來源取得價格與漲跌幅（專案已有
   `agent-core/mcp_servers/max_mcp_server.py` 可供對接）。
2. **AC-2.2** WHEN 行情請求成功 THEN 系統 SHALL 以回傳值更新對應交易對的最新價與漲跌幅，
   且每筆價格必須正確對應到其交易對標籤，不可錯配。
3. **AC-2.3** WHEN 行情請求失敗或逾時 THEN 系統 SHALL 保留前一輪數字不清空，
   並將 `hud.meta.source` 降級為 `'sample'` 或 `'mock'`（視情境而定）。
4. **AC-2.4** THE 跑馬燈徽章 SHALL 依 `hud.meta.source` 動態顯示：
   - `live` → 「MAX · 即時」
   - `sample` → 「MAX · 快照」
   - `mock` → 「MAX · 模擬」

---

## 需求 3 — 顯示主流大幣交易對

**使用者故事：** 作為訪客，我想一眼看到大家最關心的幣種，而不是一堆冷門幣。

### 驗收條件

1. **AC-3.1** THE 系統 SHALL 使用固定的主流幣白名單，建議幣種為：
   `BTC, ETH, SOL, XRP, DOGE, USDT, ADA`（共 7 個，最終清單可調整）。
2. **AC-3.2** 白名單 SHALL 定義在單一常數來源（例如共用 config 檔或常數模組），
   TickerStrip 與 feeds 皆從該來源讀取，消除目前兩處各自寫死的同步風險。
3. **AC-3.3** 白名單順序即為畫面顯示順序，固定不變。
4. **AC-3.4** IF 白名單中某交易對在 API 回傳中不存在 THEN 該欄位顯示佔位符，
   不影響其他欄位，亦不改變順序。

---

## 需求 4 — 價格格式化

**使用者故事：** 作為訪客，我希望價格的小數位數合理，不要在大數字後面出現無意義小數。

### 驗收條件

1. **AC-4.1** WHEN 價格 ≥ 1,000 TWD THEN 顯示整數並加千分位逗號（例如 `3,412,000`）。
2. **AC-4.2** WHEN 價格 ≥ 1 TWD 且 < 1,000 THEN 顯示兩位小數（例如 `32.48`）。
3. **AC-4.3** WHEN 價格 < 1 TWD THEN 顯示六位小數（例如 `0.000748`）。

---

## 需求 5 — 保持既有約束

**使用者故事：** 作為開發者，我不想改了跑馬燈就破壞 e2e 測試。

### 驗收條件

1. **AC-5.1** 跑馬燈骨架 SHALL 在掛載後保持固定，不因 API 回傳順序或內容觸發 DOM 重建。
   既有 e2e 斷言「`#hud-root` childList 變動為 0」必須繼續通過。
2. **AC-5.2** `LiveText` 的 `fmt` / `color` 函式 SHALL 保持穩定參考（使用 Map 快取或等效策略）。
3. **AC-5.3** WHEN URL 帶有 `?fast=1` 參數 THEN 不啟動輪詢（e2e 依賴此行為）。
4. **AC-5.4** 輪詢間隔 SHALL 維持 ≥ 5 秒，且使用遞迴 setTimeout（不用 setInterval）。
