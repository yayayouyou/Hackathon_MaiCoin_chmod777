# 數位廣場

把「討論社群 + 交易所情報 + 現貨交易面板」包裝成一個可以走動的像素風世界。WASD 或滑鼠點擊移動，走近互動點按 `E` 開啟資訊視窗，隨時可打開角色訊息窗操作 MAX 交易所現貨。

目前所有資料都是假的，但**資料層從第一天就是 async**，接後端時 UI 一行都不用改。

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 132 項端到端驗證（會自己起 dev server）
npm run build      # tsc --noEmit && vite build
```

| 網址參數 | 作用 |
|---|---|
| `?debug=1` | 畫出碰撞盒、鏡頭死區、互動範圍；並開放 `window.__game()` 讀取座標與狀態 |
| `?failApi=1` | 讓 `src/api/` 的所有呼叫失敗，用來檢查每個面板的錯誤狀態 |

## 架構：三層，邊界很明確

```
┌──────────────────────────────────────────────────────┐
│  React（src/ui/）   只有彈窗面板，以人類速度開關        │
├──────────────────────────────────────────────────────┤
│  uiStore            activePanel / scene / 暱稱 / 收藏  │
│                     ↕ 約 60 行的橋接                   │
├──────────────────────────────────────────────────────┤
│  遊戲（src/game/）  原生 Canvas，60fps 命令式迴圈      │
│                     + 自己直接操作的世界標籤 DOM 層    │
└──────────────────────────────────────────────────────┘
                ↓ 兩層都只透過這一個邊界取資料
┌──────────────────────────────────────────────────────┐
│  src/api/           全 async。今天回假資料，明天 fetch │
└──────────────────────────────────────────────────────┘
```

### 四個關鍵決策（動手改之前請先讀）

**1. 每幀變動的東西不進 React。**
`[E]` 提示、傳送門名牌、玩家暱稱每一幀都在移動。若走 React state 會逼元件每秒重繪 60 次，所以它們由 [`src/game/worldLabels.ts`](src/game/worldLabels.ts) 直接操作 DOM。React 只擁有彈窗。

`npm test` 有一項專門守住這件事：走動 2 秒期間 `#ui-root` 的 DOM 變動次數必須是 **0**。

**2. 中文字一律走 DOM，不畫進 backbuffer。**
內部解析度只有 480×270 上下，8px 的中文字整數放大後會糊成一團。名牌與提示都是疊在 canvas 上的 DOM 元素，字是螢幕原生解析度。也因此不需要手工刻中文點陣字型（那不可行）。

**3. 整數倍縮放不能妥協，所以改成伸縮視野。**
非整數倍會讓一個來源像素跨到兩個螢幕像素上，即使關掉平滑化也會出現寬度不一的鋸齒。[`src/game/core.ts`](src/game/core.ts) 的做法是先取最接近的整數倍率，再把 backbuffer 撐成剛好填滿視窗的尺寸：

| 視窗 | 倍率 | backbuffer |
|---|---|---|
| 1920×1080 | 4x | 480×270 |
| 1440×900 | 3x | 480×300 |
| 1366×768 | 3x | 456×256 |
| 430×820（手機） | 1x | 430×820 |

倍率用 `round` 而不是 `floor`：`floor` 在 1366×768 會選 2 倍，backbuffer 變成 683×384，世界範圍大到房間裝不下。

**4. 打光是兩道，不是一道。**
[`src/game/render.ts`](src/game/render.ts) 的 `drawLighting()` 先用 `multiply` 把環境色乘上整個世界壓暗，再用 `lighter` 把同一批光源加回去。

只用 `multiply` 的版本走不通：它的上限是「材質原本的顏色」，光池再強也亮不上去，所以要有對比就只能把環境光壓得很暗 —— 結果整個畫面暗到看不清東西。加第二道 additive 之後，環境光可以拉到 0.8 保持明亮，對比交給加亮那道負責。

光源不寫在房間定義裡，由 `propLights()` 從道具推導（[`src/game/props.ts`](src/game/props.ts)），所以新增會發光的道具不必額外維護一份光源清單。地板材質則是每個房間自己選（`Room.floor`）—— 三個房間若共用同一塊地板，光的顏色再怎麼換都還是同一個空間。

三個場景各有自己的材質與主色，這是它們讀起來像不同地方的主要原因：

| 場景 | 地板 | 主色 |
|---|---|---|
| 大廳 | 明亮冷灰石板 + 黃銅嵌線 | 青（`cyan`） |
| 討論室 | 左半深色科技磚（Agent 區）+ 右半暖色地毯（討論區） | 依討論主題，光的顏色另由情緒決定 |
| MAX 情報室 | 深藍機構石材 + 品牌藍嵌線 | MAX 品牌藍（`max`） |

新增 accent 時要同步三處：`Accent` 型別、`props.ts` 的 `ACCENT` 表、`styles.css` 的變數與規則。前兩處 TypeScript 守得住，**CSS 守不住** —— 漏掉只會靜靜退回青色，所以 `npm test` 有一條專門在檢查。

討論室還多一層：房間的光由 `RoomInfo.sentiment`（-100~100）決定，偏多偏綠、偏空偏紅。12 間討論室共用同一份場景，情緒是它們看起來不一樣的主要來源。sentiment 刻意放在 `RoomInfo` 而不是只放在 `Report` 裡 —— 遊戲層因此不必為了一個數字在載入場景時 await 一次 API。

## 接後端

只需要動 [`src/api/index.ts`](src/api/index.ts)。把 `settle()` 換成 `fetch()`，其他檔案不用碰。

```ts
getRooms()      getReport(roomId)    getThread(roomId)   postMessage(...)
getMarkets(q)   getBalances()        placeOrder(o)
getNews()       getEvents()          askBot(text)
```

兩個刻意放進去的東西，不要拿掉：

- **每次呼叫延遲 120–300ms**。逼每個面板從第一天就有真的 loading 狀態，而不是接後端時才發現整輪 UI 都要補。
- **`?failApi=1`**。逼 error 狀態被實際走過一遍。

行情目前是 3 秒輪詢一次（`getMarkets` 回抖動過的價格）。日後若改 WebSocket 推送，只改 api 層實作，面板不動。

### 交易所金鑰

`src/state.ts` 的 `creds` **只活在模組變數裡，絕不寫 localStorage**。交易所 API Key 放在瀏覽器本來就不安全 —— 任何一個 XSS 都能讀走，等於交出帳戶。寫進 localStorage 只是把風險從「分頁存活期間」延長成「永久」。

真正要接 MAX API 時，**HMAC 簽名必須在自己的後端完成，金鑰永遠不進瀏覽器**。現在的表單只是先把 UI 的閘門邏輯做出來。

### 美術是純文字的

沒有任何圖檔。角色與地磚都是「一個字元一個像素」的字串陣列寫在 `src/art/` 裡：

```ts
const BASE_DOWN = [
  '....00000000....',
  '..00ffffffff00..',
  '.0fd80ddd80ddf0.',   // 大眼 + 左上一點眼白高光
  // ...
];
```

可版控、可 diff、可直接改。角色是 16x25 的 Q 版比例（頭 14 + 身 5 + 腿 5，約 1.8 頭身）：頭寬 14px 比肩膀還寬、沒有脖子、2x2 的大眼加一點高光 —— 這幾項少做一樣就會變成「頭比較大的寫實角色」。走路 4 幀之間只有腿部（最後 5 行）與 1px 的身體晃動不同，所以只手繪 3 套上半身 + 6 套腿部，其餘靠合成。

上半身的第 0 行必須留空：`bob()` 是把整份上半身往上移一行，那行若有內容，通過幀的頭頂輪廓會被裁掉。有一條驗證在守這件事。

`npm test` 的第一組套件會檢查每一份像素圖的行寬一致、字元都在調色盤內 —— 手排像素圖最常犯的錯就是某行少打一個字元。

## 已知限制

- **沒有尋路**。點擊移動是直線 + 沿牆滑動。從上方接近 MAX 服務台會被檯面擋住，要點兩次或繞路。走不到的目標 0.7 秒後會自動放棄，光圈不會卡住。
- **不做多人**。討論串與 NPC 都是假資料。
- **直立手機**視野可能比房間還高，房間會垂直置中、上下留邊 —— 房間本來就是橫向構圖。
- **不做虛擬搖桿**。手機靠點擊地面移動、點擊互動點自動前往。
- 沒有音效。

## 操作

| 按鍵 | 動作 |
|---|---|
| `WASD` / 方向鍵 | 移動 |
| 滑鼠左鍵 | 移動到該處；點在互動點上會走過去並自動觸發 |
| `E` | 與最近的互動點 / 傳送門互動（也可直接點浮動提示） |
| `Enter` | 開 MAIA 對話 dock。**非模態** —— 它不碰 `activePanel`，世界繼續跑 |
| `Z` | 全景 ⇄ 跟隨。進場預設全景（看得到整個空間、每個互動點都掛著名牌），角色一動就自動切跟隨 |
| `I` | 開關角色訊息窗 |
| `ESC` | 關閉彈窗（在 dock 的輸入框裡是把焦點還給世界，不是關掉 dock） |
