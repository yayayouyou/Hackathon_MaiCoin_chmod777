## 三、MAX 的功能缺口(切入點,仍然成立)

核心發現:**MAX 目前幾乎沒有任何 AI / 分析功能** —— 只有「即時報酬(未實現 ROI 快照)」與「純價格到價通知」。而全球大所已把 AI 當標配:

| 功能 | Binance | Coinbase | OKX | **MAX(現況)** |
|---|---|---|---|---|
| 損益 / PnL 分析 | Portfolio Insight | Tax Center + PnL | Onchain PnL | 僅未實現 ROI 快照 |
| 交易行為分析 | Behavior Review | 部分 | — | **無** |
| 對話式 AI / 自然語言下單 | 第三方 | Coinbase for Agents | OnchainOS AI Skills | **無** |
| 情緒 / 市場智能 | Square + AI | — | 鏈上 feed | **無** |
| 稅務報表 | 有 | Tax Center | 有 | 僅 CSV 匯出,不計算 |

**排序後的切入點(價值 × 可行性):**

1. 中文 grounded 對話投資助理 —— MAX 完全沒有
2. 交易行為分析(FOMO / 追高殺低 / 過度交易偵測)—— 散戶虧損主因是行為
3. 對話式一鍵下單 —— MAX 下單全手動、機器人介面多年未進化
4. 台灣在地已實現損益 / 稅務報表 —— 剛需、無人做好、黏著度最高
5. 已實現損益歷史 + 績效歸因 —— MAX 只有當下快照,無歷史曲線
6. 智慧提醒(超越純價格)—— 部位集中度、風險、機會

**對評審(MaiCoin 本人)最有殺傷力的一句話:「這些缺口,每一個都能直接變成 MAX 的產品功能。」**

用戶痛點補充(可寫進商業段):風控/KYC 過嚴、出金延遲、無已實現損益、無稅務計算、規則型機器人多年未進化、介面偏複雜。

## 四、MAX API 能力盤點

**MAX API v3**(REST,base `https://max-api.maicoin.com`,另有 WebSocket):

| 類別 | 端點 | 金鑰 | 風險 |
|---|---|---|---|
| 公開行情 | markets / currencies / ticker(s) / depth / trades / k(K線) / index_prices | 免 | 零 |
| 私有帳戶 | info(VIP 等級)/ wallet/{spot\|m}/accounts / orders / wallet/trades / deposits / withdrawals / converts / rewards | 需(唯讀) | 低 |
| 交易下單 | POST wallet/{type}/order / cancel / cancel_all | 需(trade 權限) | 高 |

- 訂單類型:limit / market / stop_limit / stop_market / post_only / ioc_limit
- 認證:HMAC-SHA256(`X-MAX-ACCESSKEY` / `PAYLOAD` / `SIGNATURE`)
- 速率:1200 req/分;手續費 Maker 0.08% / Taker 0.16%

### 我們的實作

`agent-core/skills/max_exchange/max_private.py` —— **自建 HMAC-SHA256 簽章**(GET/POST/DELETE 共用),覆蓋 13 個唯讀端點 + 下單撤單。

> **與舊文件的差異**:舊 `競爭情報與策略.md:103` 規劃「接 `bistin/max-mcp-server`」。實際上 MAX 串接是 **100% 從零自建**,全庫 grep 不到 `bistin` / `max-mcp-server` / `max-api-skill`。
>
> 簡報上要主動說明為何自建:自建版覆蓋端點更多、可直接把風控層內嵌在呼叫路徑上。另一個講法是把 `agent-core/mcp_servers/max_mcp_server.py` 定位成「主辦 MCP 的超集」。

「真的用了 Private API 而不是只查餘額」的最強證據是 `position_ledger.fetch_events()` —— 它用 my_trades / converts / rewards / fund_transactions / accounts **五支端點做對帳**。

### 三大工程風險(現場 demo 前必須處理)

1. **撮合非同步** —— 下單回應只代表「已受理」,需輪詢 `GET order` 確認終態
2. **簽章嚴格** —— nonce 需近伺服器時間且一次性、path 一致。⚠️ `max_private.py` 的 nonce **只用本機時鐘,沒有伺服器時間校準**;筆電睡眠喚醒後時鐘漂移會讓私有 API 整組 401,而錯誤訊息完全不指向時鐘。前一晚開 NTP 同步,demo 腳本第一步放 `get_max_member_info()` 驗簽
3. **速率 / 費用** —— 密集輪詢會觸頂(改走 WS);市價 = taker 較貴,可用 post_only 走 maker

**金鑰安全**:最小權限發金鑰 —— demo 只給 read;要下單才加 trade;**絕不給 withdraw**;可設 IP 白名單。

| 風險 | 成因 | 處置 |
